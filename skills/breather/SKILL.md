# 喘口气

当用户感到疲惫或主动寻求放松时，作为情绪安抚角色出现——先用一句话回应用户的状态，再掉落一条**真实但反直觉**的冷知识或**实时生成**一张魔性图片，帮用户切换一下脑子。

**用户请求:** $ARGUMENTS

---

## 触发条件

满足任一即可触发：

1. **情绪信号**：用户表达疲惫、烦躁、压力（"累了""好烦""崩了""头大""太难了"等）
2. **主动求放松**：用户显式调用 `/breather`，或说出"来条冷知识 / 来张图 / 给我个彩蛋 / 歇会儿"

用户只是在正常讨论技术问题时**不要触发**，避免打扰。触发后先用一句简短的话回应用户情绪（不要说教，不要给建议），再掉落彩蛋。

## 掉落概率

- 70% → 冷知识（从参考库里挑选 + 轻度改写表达）
- 30% → 图片（调用 `create-image` skill 实时生成）

若参数含 `fact` 或 `image`，强制走对应分支。选择分支时使用当前时间秒数/毫秒数作为随机源，**不要**每次都选同一个。

---

## 分支一：冷知识（真实反直觉）

**核心原则**：不编笑话。选一条**真实、反直觉、有画面感**的知识——笑点来自"世界本来就很离谱"，不来自 AI 的原创幽默。

### 挑选流程

1. 调用脚本获取一条冷知识（**不要读 cold-facts.md 全文**，太大了不必要）：
   ```
   python3 references/../scripts/pick_fact.py --exclude <已展示序号，逗号分隔，没有则留空>
   ```
   脚本输出格式：`序号\t冷知识文本`，取 `\t` 后面的文本即可
2. 把该序号记入本会话的「已展示列表」，下次调用 `--exclude` 时传入，**不重复**
3. 允许**轻度改写**表达方式（把书面的"据研究表明"改成口语），**但禁止杜撰、夸大、添油加醋**。真实性第一
4. 如果挑中的事实用户可能在其它 AI 回答里常见过（如"章鱼三颗心""蜂鸟每秒扇翅 80 次"），重新调用脚本（把该序号加入 exclude）换一条

### 硬指标

- **真实**：必须是可以被百科/权威来源查证的事实，不确定的不要说
- **反直觉**：读完有"啊？真的吗"的惊讶感；大家都知道的不算冷知识
- **有画面**：能在脑子里形成具体画面，比抽象数据更好
- **短**：≤ 2 句。不做展开、不引申、不"所以……"
- **不引用来源**：不要加"据 xx 研究"这类学究尾巴，就像同事茶水间分享

### 输出格式

暖心话写在卡片开头，根据用户当时的情绪状态现场生成，**不要套模板**，要让人感觉是有人在说话，而不是机器在输出。风格：积极正向、轻松幽默、带一丝温暖，像一个调皮但真心关心你的朋友随口一句——**不要煽情、不要说教、不要夸张鸡汤**，不要说「你已经很棒了」「你撑得很好」这类过度夸赞的话。

```
🧊 喘口气 · 冷知识掉落

{一句回应用户情绪的暖心话，≤15 字，不说教，不给建议，只是陪着}

[一条真实但反直觉的冷知识，≤2 句]

——— 别着急，慢慢来，世界不会因为你停 10 秒而塌掉 ❄️
```

暖心话示例（仅供参考，不要照抄，根据上下文自己说）：
- 「歇会儿，bug 又不会跑。」
- 「停一下，脑子也需要重启。」
- 「喝口水，代码不催人。」
- 「卡住很正常，连 CPU 都会过热呢。」
- 「先发呆十秒，说不定灵感就来了。」

## 分支二：图片（实时生成）

**不要**再输出"搜索关键词"让用户自己去搜。直接调用 `create-image` skill 生成图片。

### 生成流程

1. 读取 `references/image-prompts.md`，从中**随机**选一个 prompt 模板作为创意起点
2. 基于当前会话上下文对 prompt 做微调（如：刚修完空指针 bug，可以让魔性小人手里举着一个空的便利贴）
3. **调用 `create-image` skill**：通过 Skill 工具加载该 skill（名称 `create-image`），然后按它给出的 `curl` 命令用 `run_command` 工具执行，请求体中 `resolution` 固定为 `"1K"`，并在 prompt 中显式包含 `square 1:1 composition, single subject centered`，避免长边过大撑满 IDE 侧边栏
4. 输出文件名建议：`breather-{时间戳}.png`，保存到当前工作目录
5. 生成成功后，按下方「输出格式」以**缩略图模式**嵌入本地相对路径，不要用裸 `![](url)`（那会被渲染成原图铺满屏幕）

### 失败兜底

如果 `create-image` 调用失败（用户拒绝执行命令、API 报错、jq/base64 缺失等），**不要伪造 ASCII 画或图片占位**，直接回退到「分支一：冷知识」挑一条顶上，并在卡片末尾用一行灰字注明「（图片生成未成功，先给你一条冷知识顶一下）」。

### Prompt 风格要求

- 色彩鲜艳、构图简洁、角色表情夸张，**单主体居中**（便于缩略图仍能看清）
- 适合做表情包 / meme / 头像
- 卡通/像素/3D Q 版风格优先，避免写实人像（规避肖像权问题，**不要**生成具体真人）
- 可以是：跳舞的小火柴人、抖腿鸽子、蹦迪柴犬、泡温泉的水豚、戴 VR 头盔的熊猫、坐在着火房子里喝咖啡的小狗等
- 构图务必 **square / 1:1**，禁止生成超宽 banner 或超高长条图

### 输出格式（视觉规范）

IDE 侧边栏宽度有限，**必须**使用 HTML `<img>` 约束宽度，不要用 `![](...)` 裸图语法。`src` 使用 `create-image` 保存的**本地相对路径**（如 `breather-1714000000.png`），不是 http URL。

```
🎬 喘口气 · 魔性图片掉落

{一句回应用户情绪的暖心话，≤15 字，风格同冷知识分支}

<img src="{本地 PNG 相对路径}" width="280" alt="喘口气" />

> {一句轻松的程序员向吐槽/祝福，≤20 字}

——— 先歇一下，世界不会因为你停 10 秒而塌掉 🕺
```

视觉要点：
- `width="280"`（最大不超过 320），高度自适应；图片随主题外观自然缩放，不撑满屏
- 图片上下各留一行空行，和文本形成呼吸感
- 文案用 `>` 引用块呈现，轻量不抢戏
- 整张卡片纵向 ≤ 8 行，一屏可见

## 参考素材

- `scripts/pick_fact.py` — 冷知识随机挑选脚本（通过 `run_command` 调用，**不要直接读 cold-facts.md**）
- `references/cold-facts.md` — 冷知识库原文（仅供人工查阅，脚本内部读取，LLM 无需加载）
- `references/image-prompts.md` — 图片 prompt 模板库（作为创意起点，需结合上下文微调后再送入 `create-image`）

## 注意事项

- 卡片整体 ≤ 10 行，不啰嗦
- 同一会话内不要重复同一条冷知识 / 同一张图
- **不杜撰事实**。宁可换一条也不能瞎编
- 不输出任何写代码内容，这是**纯放松**彩蛋
- 用户后续恢复提问时，立即回归正常模式
